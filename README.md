# COMS Suite

**공시원문 다운로드 · 비교기업 재무분석 — DART · EDGAR**
(COMS = comparable companies, 비교기업)

감사·실사 업무에서 반복되는 두 가지 일을 창 하나에서 처리합니다.

| 탭 | 하는 일 |
|---|---|
| **공시원문 다운로드** | 회사·연도별 공시원문을 일괄로 받아 `회사명/보고서종류_연도/` 로 정리하고, 바로 읽을 수 있는 HTML과 재무제표 4종 엑셀로 변환 |
| **비교기업 재무분석** | 같은 공시에서 재무제표를 받아 매출액·영업이익·EBITDA·**EV/EBITDA** 까지 나란히 놓은 HTML 리포트 작성 |

**한글로 쓰면 DART(한국), 영문이나 티커로 쓰면 EDGAR(미국)** 에서 찾습니다.
한 칸에 섞어 써도 됩니다.

```
삼성전자
SK하이닉스
AAPL
NVDA
```

거의 전부 파이썬 표준 라이브러리로 돌아갑니다. **재무제표 엑셀 저장에만 `openpyxl`이
필요하고**, 없으면 그 항목만 건너뜁니다(나머지 기능은 그대로 동작합니다).
리포트도 외부 차트 라이브러리 없이 SVG를 직접 그리므로,
인터넷이 끊긴 사내망에서도 파일 하나만 열면 그대로 보입니다.

---

## 왜 합쳤나

원래 따로 만든 두 프로그램인데, 쓰다 보니 **같은 것을 두 번 하고 있었습니다.**

- 같은 인증정보(DART 인증키 · EDGAR 연락처)를 두 곳에 넣어야 했고
- 같은 기업코드 색인(`CORPCODE.xml`, 30MB)을 각자 읽어 시작이 두 배로 느렸고
- 회사명으로 회사를 찾는 코드가 양쪽에 똑같이 들어 있었습니다

합친 뒤에는 인증정보를 창 위에 한 벌만 두고, 색인은 **먼저 필요한 탭이 읽으면
나머지 탭은 그것을 그대로 받아 씁니다**(자물쇠로 한 번만 읽도록 보장).

## 설치와 실행

```bash
git clone https://github.com/dudgns0825-alt/coms-suite.git
cd coms-suite
python app.py
```

요구사항은 **Python 3.8 이상**입니다 (tkinter 포함 기본 설치판).
재무제표 엑셀을 쓰려면 `pip install openpyxl` 한 줄만 더 하면 됩니다.

### 인증정보

창 위쪽 [인증정보] 칸에 넣고 **[저장]** 을 누르면 `config.txt` 로 저장됩니다.
(`config.example.txt` 를 복사해 직접 만들어도 됩니다.)

**DART — 인증키가 필요합니다.**
<https://opendart.fss.or.kr> → 인증키 신청/관리 → 신청 (무료, 즉시 발급, 40자리).
하루 20,000건까지 조회할 수 있습니다.

**EDGAR — 인증키가 없습니다.** 대신 `이름 이메일` 형식의 연락처를 넣습니다.

```
Hong Gildong hong@example.com
```

신청 절차는 없지만 SEC는 요청자 신원을 User-Agent에 실어 보내도록 요구하며,
없으면 **403으로 거절**합니다. 하루 한도는 없고 초당 10건 제한만 있습니다.
한국 회사만 볼 거라면 비워 두어도 됩니다(반대로 미국 회사만 본다면 DART 키가 필요 없습니다).

`config.txt` 는 `.gitignore` 에 등록되어 있습니다.

처음 실행하면 기업 목록을 자동으로 받습니다 —
DART는 `CORPCODE.xml`(약 30MB, 11.8만개 법인), EDGAR는 `EDGAR_TICKERS.json`(약 0.8MB, 1만여개).
갱신하려면 해당 파일을 지우고 다시 실행하면 됩니다.

# 탭 1 · 공시원문 다운로드

회사명과 사업연도, 받을 보고서 종류를 고르고 [다운로드 시작]을 누르면 됩니다.

```
범한산업/
└─ 감사보고서_2024/
   ├─ 범한산업_2024_감사보고서.zip             원본 공시원문
   ├─ 범한산업_2024_감사보고서.xml             압축 해제된 원문
   ├─ 범한산업_2024_감사보고서_보기.html       ← 브라우저로 바로 열림
   ├─ 범한산업_2024_감사보고서_재무제표.xlsx   ← 재무제표 4종을 시트별로
   └─ .done_20250409001093                    완료 표식 (이어받기용)
```

파일명은 `회사명_사업연도_보고서명` 입니다. 접수번호가 아니라 내용으로 읽히므로
조서에 그대로 옮겨도 무엇인지 알아볼 수 있습니다.
한 사업연도에 여러 건인 보고서(분기보고서·10-Q)는 뒤에 결산월이 붙습니다.

### 재무제표 엑셀

[재무제표 엑셀]에 체크하면 공시원문에서 **재무상태표·손익계산서·자본변동표·현금흐름표**를
찾아 원문 표 그대로 엑셀 한 파일에 담습니다. 재무제표마다 시트가 따로 생기고,
연결·별도가 모두 실린 보고서는 `재무상태표(연결)` `재무상태표(별도)` 로 각각 만듭니다.
손익계산서와 포괄손익계산서를 따로 내는 회사는 한 시트에 위아래로 이어 붙입니다.

숫자는 숫자로 들어가므로(`(1,234)` → `-1234`) 시트에서 바로 더할 수 있고,
계정명·주석번호·들여쓰기는 원문 표기 그대로 남습니다.
시트 맨 위에 회사·보고서·사업연도·접수번호를 적어 두어 출처를 되짚을 수 있습니다.

#### 합계검증 시트

맨 앞에 **「합계검증」** 시트가 붙습니다. 재무제표가 스스로 만족해야 하는 항등식을
읽어 온 숫자로 다시 계산해, 기수(열)마다 계산값·표시값·차이·판정을 적습니다.

| 재무제표 | 검산 |
|---|---|
| 재무상태표 | 자산 = 부채 + 자본 · 자산총계 = 유동 + 비유동 · 부채총계 = 유동 + 비유동 |
| 손익계산서 | 매출총이익 = 매출액 − 매출원가 · 영업이익 = 매출총이익 − 판관비 · 당기순이익 = 세전이익 − 법인세 · 총포괄손익 = 당기순이익 + 기타포괄손익 |
| 자본변동표 | 기말자본 = 기초자본 + 기중 변동 합계 (열마다·기수 블록마다) |
| 현금흐름표 | 증감 = 증감 줄 위 상위항목 합계 · 기말현금 = 기초현금 + 증감 |

표에 없는 항목(서비스업의 매출원가 등)은 조용히 건너뜁니다 — 없는 것과 틀린 것은
다르기 때문입니다. **'차이'로 찍히면 표를 잘못 읽었거나 회사가 낸 표가 어긋난다는
뜻**이므로 원문을 확인하십시오. 실제로 삼성전자 5개년·두산에너빌리티·신한지주·
비에이치아이·호반건설·삼성디스플레이·리벨리온은 전건 일치했고, 차이가 남은 두 건은
**공시된 표 자체의 부호 오류**였습니다(한텍 2026.1Q 비교표시 확정급여 재측정요소,
피케이밸브 FY2023 재평가잉여금 — 둘 다 합계 열과 부호가 반대).

소계와 그 내역을 이중으로 더하지 않도록, 원문의 들여쓰기(전각공백)로 상위·하위를
가려 냅니다. 소계를 위에 두고 내역을 들여쓰는 표와, 소계와 내역을 같은 줄 높이에
나란히 두는 표를 모두 처리합니다.

재무제표 API(`fnlttSinglAcntAll`)는 계정과 금액만 주므로 표의 생김새는 원문에만 있고,
사업보고서를 내지 않는 비상장 외감법인은 API에 자료 자체가 없어 원문이 유일한 출처입니다.
**미국(EDGAR) 공시는 대상이 아닙니다** — 10-K는 영문 서식이라 재무제표 이름과 구성이 다릅니다.

### 비상장 외감법인 감사보고서

DART 웹에서 잘 찾아지지 않는 것이 **비상장 외부감사대상 법인**입니다.
사업보고서 제출 의무가 없어 감사보고서가 단독 공시로만 올라오는데,
조회 경로가 상장사와 다릅니다.

| 회사 | 사업보고서 | 감사보고서 단독공시 |
|---|---|---|
| 삼성전자 (상장) | 있음 | **없음** |
| 삼성디스플레이 (비상장) | **없음** | 있음 |

정확히 반대입니다. 그래서 정기공시(`A`)와 외부감사관련(`F`)을 **둘 다** 조회합니다.

### 미국(EDGAR) 공시

보고서 종류 체크박스는 한국 기준이며, 미국 회사에는 같은 성격의 서식으로 연결됩니다.

| 체크박스 | DART | EDGAR |
|---|---|---|
| 사업보고서 | 사업보고서 | `10-K`, `20-F` |
| 반기보고서 | 반기보고서 | — (미국은 반기보고서가 없습니다) |
| 분기보고서 | 분기보고서 | `10-Q` |
| 감사보고서 | 감사보고서 | — (감사의견이 `10-K` 안에 포함됩니다) |

`10-K/A` 처럼 정정된 서식도 함께 받습니다(DART의 `[기재정정]` 과 같은 취급).
폴더는 미국 서식명 그대로 만듭니다 — 조서에서 원문을 대조할 때 이름이 어긋나지 않도록.

### 원문이 그냥 열리지 않는 이유

DART가 주는 공시원문은 확장자가 `.xml` 이지만 **표준 XML이 아닙니다.**
자체 스키마(`dart4.xsd`) 기반이라 브라우저는 파싱 에러를 내고, 파이썬 표준 파서로도 읽히지 않습니다.

1. 본문의 `R&D` 처럼 `&` 가 이스케이프되지 않음 (`&amp;` 여야 함)
2. `<PGBRK>`, `<IMG>` 처럼 닫는 태그가 없는 SGML식 빈 태그

다만 구조 자체는 HTML과 거의 같습니다(`TABLE/TR/TD/TH`).
그래서 엄격하게 파싱하지 않고 **태그 이름만 HTML로 치환한 뒤 브라우저의 관대한 파서에 맡깁니다.**

**인코딩 함정** — 2021년 이전 공시는 XML 선언이 거짓말을 합니다.
선언은 `utf-8` 인데 실제 바이트는 CP949입니다. 그래서 선언을 무시하고
`utf-8 → cp949` 순서로 디코드를 시도합니다. 순서가 중요합니다 —
CP949는 대부분의 바이트를 받아들여서 먼저 시도하면 UTF-8 문서까지 깨진 채로 "성공"합니다.

# 탭 2 · 비교기업 재무분석

대상회사와 비교기업을 적고 [자료 받고 리포트 만들기]를 누르면
연도별 재무제표를 받아 지표를 계산하고 HTML 리포트를 만듭니다.

```
EBITDA   = 영업이익 + 감가상각비·무형자산상각비
EV       = 시가총액 + 순차입금(리스부채 포함)
시가총액 = 기준일 종가 × 상장주식수
```

시가총액 기준일과 적용 주가(당일 종가 / 5일·20일 평균)를 직접 정할 수 있습니다.
통화가 다르면 대상회사 통화 기준으로 환산해 한 차트에 놓습니다.

## ★ 비상장회사도 비교할 수 있습니다

비상장이라고 다 같지 않습니다. 두 갈래로 갈리고, 둘 다 됩니다.

| | 재무제표 API | 처리 |
|---|---|---|
| 비상장 + 사업보고서 제출 (SK온·에이치디현대오일뱅크 등 회사채 발행사) | 나옵니다 | 상장사와 똑같이 |
| 비상장 + 감사보고서만 (삼성디스플레이·쿠팡·우아한형제들·애플코리아 등) | `[013]` 없음 | **감사보고서 원문의 재무제표 표를 직접 읽습니다** |

감사보고서 단독공시에는 **XBRL 태그가 없습니다**(삼성전자 FY2025 사업보고서가
태그 6,000개인데, 삼성디스플레이 FY2025 연결감사보고서는 44개뿐이고 사업연도
컨텍스트도 없습니다). 그래서 표를 글자로 읽되, 값을 곧이곧대로 집지 않고
**재무제표가 스스로 만족해야 하는 항등식이 성립하는 열만** 씁니다.

| 재무제표 | 검산식 |
|---|---|
| 재무상태표 | 자산총계 = 부채총계 + 자본총계 |
| 손익계산서 | 매출총이익 = 매출액 − 매출원가 / 영업이익 = 매출총이익 − 판관비 / 영업이익 = 영업수익 − 영업비용 / 당기순이익 = 세전이익 − 법인세비용 |
| 현금흐름표 | 기말현금 = 기초현금 + 현금의 증감 |

당기·전기 두 열 모두 항등식을 만족하므로, **통과한 열 중 가장 왼쪽**을 당기로 봅니다
(우리말 재무제표는 당기를 먼저 적습니다). 열은 오른쪽 끝에서부터 셉니다 —
줄마다 주석칸이 있다 없다 해서 왼쪽 기준으로는 줄끼리 어긋납니다.

읽어 낸 값은 재무제표 API와 **같은 모양의 계정 행**으로 바꿔 넘기므로,
그 뒤의 지표 계산·주석 감가상각비 보충·리포트는 상장사와 똑같은 길을 탑니다.

검증한 회사(2023~2025):

| 회사 | 2025 매출 | 2025 영업이익 | 비고 |
|---|---|---|---|
| 삼성디스플레이 | 29.7조 | 4.07조 | 감가상각비도 주석에서 자동 확보 |
| 쿠팡 | 45.5조 | 2.29조 | |
| 우아한형제들 | 5.28조 | 0.59조 | 영업수익−영업비용 형식 |
| 애플코리아 | 7.37조 | 0.25조 | 9월 결산, 비용을 음수로 표기 |
| 오비맥주 | 1.78조 | 0.35조 | |

비상장회사는 주가가 없으므로 **시가총액·EV·EV/EBITDA·PER·PBR은 비어 있고**,
매출액·영업이익·EBITDA·부채비율 등 재무제표에서 나오는 지표는 그대로 비교됩니다.
리포트 각주에 어느 회사 자료를 감사보고서에서 읽었는지 밝혀 둡니다.

## ★ 감가상각비와 차입금은 주석에서 읽어 옵니다

**한국 대형사는 감가상각비가 재무제표 API로 오지 않습니다.**
현금흐름표의 조정 항목을 `조정` 한 줄로 묶어 제출하기 때문입니다
(삼성전자·SK하이닉스는 전 연도). 차입금을 재무상태표에 `금융부채` 로 묶어
표시하는 회사(LG디스플레이)도 본문만 봐서는 차입금을 가릴 수 없습니다.

그래서 본문에 없으면 **사업보고서 원문을 받아 주석에서 직접 읽습니다.**

**① XBRL 태그** — 원문에는 표의 숫자마다 태그가 붙어 있습니다.

```xml
<TE ACODE="ifrs-full_AdjustmentsForDepreciationExpense"
    ACONTEXT="CFY2025dFY_..._ConsolidatedMember_...">43,605,740</TE>
```

`ACONTEXT` 에 사업연도(CFY=당기, PFY=전기)와 연결/별도가 들어 있어 어느 값인지 정확히 가릴 수 있습니다.
**단위는 표마다 다릅니다** — 재무제표 표는 백만원인데 주석 표는 원 단위인 회사가 있어,
각 숫자보다 앞에 있는 가장 가까운 `(단위 : 백만원)` 표기를 그 표의 단위로 삼고
같은 문서의 매출액이 API 값과 맞는지 대조한 뒤에만 씁니다.

**② 다음 해 보고서의 전기 비교표시분** — 주석 태깅은 FY2025 보고서부터 전면
적용됐습니다(그 전에는 200~1,500개, FY2025부터 5,000~8,000개). 보고서 하나에
당기(CFY)와 전기(PFY)가 함께 태깅되므로, FY2024 감가상각비는 FY2025 보고서에 있습니다.
그 해 보고서에서 못 찾으면 다음 해 보고서까지 찾아봅니다.

**③ 표를 글자로 읽기** — 태그가 아예 없는 FY2023 이전 보고서는 주석 표를 직접 읽습니다.
문제는 한 문서에 연결·별도 주석이 같이 있고, 표마다 당기·전기 열이 있고, 단위도
표마다 다르다는 것입니다. 그래서 값을 곧이곧대로 집지 않고
**열을 전부 더한 값이 재무제표 본문의 금액과 맞는 열만** 씁니다.

| 표 | 열 합계가 맞아야 할 본문 금액 |
|---|---|
| 현금흐름표 조정 내역 | `조정`(`AdjustmentsForReconcileProfitLoss`) |
| 비용의 성격별 분류 | 매출액 − 영업이익 (= 매출원가 + 판매비와관리비) |

이 대조 하나로 연결/별도·당기/전기·단위가 한꺼번에 확인됩니다.
맞는 열이 없으면 아무것도 쓰지 않고 직접 입력으로 넘깁니다.
대조는 **0.1%** 로 빠듯하게 봅니다 — 1%로 느슨하게 잡았더니 유형자산 증감표의
어느 한 열 합계가 0.8% 차이로 통과해 엉뚱한 값(자산 한 종류분)을 물어 온 적이 있습니다.

2021~2025년 5개년 감가상각비 확보 결과(전부 자동, 직접 입력 0칸):

| 회사 | 2021 | 2022 | 2023 | 2024 | 2025 |
|---|---|---|---|---|---|
| 삼성전자 | 34.2조 | 39.1조 | 38.7조 | 42.6조 | 46.9조 |
| SK하이닉스 | 10.6조 | 14.1조 | 13.6조 | 12.6조 | 13.9조 |
| LG디스플레이 | 4.50조 | 4.56조 | 4.21조 | 5.13조 | 4.35조 |
| DB하이텍 | 0.14조 | 0.12조 | 0.13조 | 0.16조 | 0.17조 |
| 한미반도체 | 0.007조 | 0.009조 | 0.009조 | 0.010조 | 0.012조 |

태그와 표를 둘 다 읽을 수 있는 칸에서 두 방식의 값이 소수점까지 일치했고,
그 해 보고서의 당기 열과 다음 해 보고서의 전기 열도 일치했습니다.

### 차입금은 회사가 밝힌 총계와 맞을 때만 씁니다

**주석의 차입금 태그를 그냥 더하면 안 됩니다.** 재무상태표에 `차입금` 으로 표시한 줄에
사채가 이미 들어 있는 회사가 있어(SK하이닉스), 주석의 사채 내역을 더하면 이중계상됩니다.
그래서 구성요소를 더한 값이 회사가 주석에 스스로 밝힌 차입금 총계(`ifrs-full_Borrowings`)와
1% 이내로 맞을 때만 채택하고, 어긋나면 쓰지 않습니다.

리포트의 값에는 출처가 표시됩니다.

| 표시 | 뜻 |
|---|---|
| (없음) | 재무제표 본문에서 그대로 |
| **˚** | 사업보고서 주석에서 자동으로 읽음 (XBRL 태그 또는 표 대조) |
| **★** | 사용자가 직접 입력 |

## 알아 두면 좋은 것

**사업연도와 공시연도는 다릅니다.**
2025 사업연도 사업보고서는 2026년 3월에 공시됩니다.
프로그램이 묻는 연도는 **결산 사업연도**입니다.

**연도별로 따로 조회합니다.**
재무제표 API는 한 번 호출하면 당기·전기·전전기 3개년을 함께 주지만,
전기 열의 금액은 이후 재분류·수정된 값이라 당시 공시치와 다를 수 있습니다.
그래서 각 연도 보고서의 **당기 열**만 사용합니다.

**계정은 표준계정코드로 찾습니다.**
계정명은 같은 회사도 연도마다 달라지지만(`영업이익` ↔ `영업이익(손실)`)
`account_id` 는 안정적입니다. 표준계정으로 못 찾은 경우에만 계정명으로 보완합니다.

## 한계

- **순차 처리** — 회사를 하나씩 처리합니다 (API 하루 한도와 서버 부담을 고려한 선택)
- **EDGAR는 상장사만 이름으로 찾힙니다** — SEC 목록에 티커 보유 회사만 있습니다.
  비상장 제출인은 CIK를 직접 입력해야 합니다 (`320193` 또는 `CIK0000320193`)
- **20-F 제출 외국법인은 재무분석 대상 밖입니다** (다운로드는 됩니다)
- 회사 간 계정 범위는 회계정책·표시방법에 따라 다를 수 있습니다.
  기계적으로 집계한 값이므로 **인용 전에는 공시 원문 확인이 필요합니다**
- 색으로 구분할 수 있는 한도가 있어 재무분석은 대상회사 포함 **8곳까지** 비교합니다
- 통화가 다른 회사는 기준일 환율로 단순 환산합니다(손익도 기간평균환율이 아닙니다)
